# Validation quickstart

1. Follow [repository prerequisites and local development procedure](../../README.md#manual-local-development-check), including Podman socket settings and existing secrets. Restore pinned packages and keep generated lockfiles. Never copy credentials/tokens into committed artifacts.
2. Run focused document and identity tests after retaining their red evidence. Run `npm run format-check`, `npm run lint`, and `npm run check` for handoff. Missing Podman/readiness is a pending prerequisite, never a skipped passing suite.
3. Start the application manually with the existing Aspire lifecycle procedure. In the dashboard, verify Inventory, Reservations and Notifications each link to `/scalar/` on their actual browser-reachable origin. UI links remain `/scalar/`; OAuth callbacks use the separate inert `/oauth/callback` route. Verify bootstrap reconciles those exact callback URIs and origins after a restart with different allocated ports, with no wildcard or stale registration. Do not automate AppHost construction/inspection/startup in application tests.
4. Fetch `/openapi/v1.json` on each service. Confirm eight total business operations, usable schemas/status/security and zero operational routes; compare with [contract](contracts/http.md). Default Production/Testing hosts must return 404 for documents, UI and local UI assets.
5. Set `API_WEB_URL` to the current Web origin and `API_INVENTORY_URL`, `API_RESERVATIONS_URL`, and `API_NOTIFICATIONS_URL` to their printed loopback service origins with trailing slashes. Set `IDENTITY_BROWSER_ACCOUNTS_FILE` to the private account JSON fixture outside source control, populated only through filtered individual retrieval from the intended run's local secrets; optionally set `BROWSER_EXECUTABLE`. Run `npm --prefix src/Web run test:browser -- openapi.spec.ts` for documentation checks; the full `npm --prefix src/Web run test:browser` suite remains required. Keep credentials in the private fixture/local secrets only. Do not enable traces, screenshots, videos or response-body logging.
6. In Scalar authenticate through the popup as Employee. Check S256/code flow through the inert `/oauth/callback` page, unchanged fragment code/state, successful read and real reservation booking/cancellation. Run Employee then Approver login sequentially to guard against callback-router corruption; sign in as Approver in a fresh context and confirm reservation write fails 403; without credentials confirm 401. UI must report failures honestly when login is cancelled/provider unavailable. Requests change real development data.
7. Inspect browser request destinations: API traffic remains same-origin; provider authorize/token exchange reaches only registered local Keycloak. No external proxy, AI or font fetch; a fresh browser session has no restored UI tokens. API authorization and browser guards remain intact.
8. Inspect representative Aspire traces and exported telemetry for new provisioning paths and documentation requests, including controlled failure. Retain operation/outcome/correlation evidence without recording passwords, authorization codes, access/refresh tokens, bodies or personal data. Record actual revision, command/environment/result and manual observations in team evidence.

Independent reviews, latest convergence and explicit human feature acceptance remain required after these checks.
