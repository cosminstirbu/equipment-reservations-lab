# Qualification schema v2 proposal

Status: proposed preparation delta; dependent migration is held pending independent quality/security verdicts. No human approval or reviewer verdict is asserted here.

Affected source: scripts/azure-qualification.mjs qualificationDefinition, publishInitialQualificationChallenge, produceInitialQualificationProof and public prove dispatch; scripts/azure-provisioning.mjs context-only established-activation check; subsequent private proof validation/consumption, recurring producer and reviewed deploy/platform/azure/recovery-activation.json.

## Exact revision fields

New challenge/proof/consumption/reviewed-activation records use version2. Version1, absent fields and ambiguous mixtures are rejected; the current implementation's version1 sourceRevision used the infrastructure anchor and cannot be silently reinterpreted as execution evidence.

- infrastructureAnchorRevision: exact config.gitRevision, the approved generation infrastructure anchor. It need not equal current application/main HEAD.
- sourceRevision: reviewed probe-source commit. For a newly issued challenge this is the publisher's actual clean HEAD, verified against trusted GITHUB_SHA. An actor proof copies the challenge's reviewed sourceRevision; it does not relabel its own executed checkout with the anchor.
- actualProbeCodeRevision: that producer's actual clean checkout HEAD, equal to trusted GITHUB_SHA for its protected trusted-main execution. The publisher likewise records its own actual checkout. The actor's value may differ from sourceRevision after an unrelated app-only commit.

All SHA fields are full lowercase40hex. Neither command accepts a caller boolean, a caller-selected code SHA or an environment variable as a substitute for checking actual Git HEAD and cleanliness. Read actual HEAD with git; reject staged/unstaged/untracked source modifications before probing, and recheck HEAD/cleanliness before writing proof. Require GITHUB_ACTIONS=true, GITHUB_REF=refs/heads/main and HEAD=GITHUB_SHA. Hosted checkout itself must be immutable to that trusted SHA; Azure principal and Kubernetes SelfSubjectReview must match the expected actor independently.

## Exact definition identity

qualificationDefinition currently hashes azure-qualification.mjs and reviewed qualification Roles, production Roles and admission templates. V2 expands the executed-probe definition into an explicit fixed repository file closure, including any imported module that can change proof transport, identity validation, process execution, source selection, record hashing or authorization checks. A canonical manifest records each fixed relative path and SHA256 of its bytes; probeDefinitionHash is SHA256 of that canonical manifest. Missing/extra paths, traversal, symlinks or changed bytes fail. The manifest is computed from the actual clean checkout at execution and separately verified against git objects at sourceRevision and actualProbeCodeRevision, not merely copied from challenge input.

Q-D014-004 correction: a hand-written list of direct dependencies is insufficient. Commit a reviewed definition manifest whose entrypoints are the actual qualification producer and publisher dispatch. Compute the complete transitive local-module graph independently from those entrypoints, including every static import/re-export and every reachable literal dynamic import, even functions that are not called in one phase: module top-level code executes on import. This necessarily includes already-imported azure-runtime.mjs and argocd-installation.mjs and their dependencies. Parse source without executing it. Relative imports must resolve to canonical regular repository files with exact tracked paths; reject symlinks, traversal outside the checkout, missing targets and unexpected extensions. Cycles are visited once. Reject computed/dynamic loading, eval/Function/source-loader hooks and nonliteral imports unless a separately reviewed finite expansion is explicitly encoded and fully traversed; there is no automatic exclusion based on guessed runtime non-use.

The independently discovered graph must equal the committed reviewed manifest's module set at the reviewed source commit and at executed HEAD. An imported file that was omitted from the manifest is a blocking error, including a newly introduced dependency. Each graph path and its SHA256 bytes are compared across the challenge, reviewed source Git objects, executed HEAD Git objects and actual working files. Role/template-specific hashes remain separate for readable current-cluster validation. The fixed data set also includes qualification/production Roles, admission templates, all executable or interpreted assets reachable from the producer/publisher, the qualification workflow and bootstrap workflow definition, and the pinned tool lock; a data path read at module initialization or during qualification cannot be omitted merely because it is not an ECMAScript import. Record these exact paths in the reviewed manifest rather than a caller-supplied list.

Pinned runtime/package inputs are part of definition identity: package.json, package-lock.json, exact Node24.15.0, dependency names/versions/integrities and the reviewed immutable workflow actions/tool SHA256 values. Producer workflows install with npm ci --ignore-scripts, use the pinned Node runtime, validate the reviewed dependency lock and verified executables, and reject NODE_OPTIONS/NODE_PATH or custom import-loader/preload settings. External package resolution must match the lock and reviewed imports; unknown/unpinned packages or install-time lifecycle execution fail. Dependency source/version changes require a new definition manifest and initial qualification, not an app-only exception. Tests must mutate a transitive local import, add an omitted import, alter a package lock and inject a loader environment value to prove these boundaries.

Launch-boundary clarification: a JavaScript check cannot reject a preload that Node already executed. The reviewed protected workflow must clear NODE_OPTIONS/NODE_PATH and prohibit custom loader/preload command-line options before launching either npm or the producer Node process; a minimal fixed shell launch or equivalent fixed environment is an executable asset in the reviewed manifest. The producer additionally checks actual process.version/execArgv and its clean environment before loading protected operational modules, but cannot claim this retroactively undoes a prior preload. A test supplies a marker-writing preload to the real public launch boundary and proves it never executes. Direct invocation through an attacker-controlled interpreter is outside the trusted hosted producer boundary and must not be presented as qualified execution.

A conservative manifest containing all relevant repository scripts/assets is acceptable and avoids a general dependency framework. Independently parsed reachable imports must still be contained in that reviewed set; omission is not excused by the conservative naming rule. Keeping application source outside that set preserves ordinary app-only SHA independence when all actual qualification dependencies are unchanged.

An app-only later SHA is accepted only when every path in this exact reviewed closure has identical bytes at the challenge sourceRevision, the actual executed HEAD and the challenge manifest. No source change is excused by its commit message, path outside a guessed prefix or a claim that it was unrelated. Current role/template bytes and actual installed Role/RoleBinding subjects/hashes must still match the validated activation. If these definitions change, a new reviewed challenge, both actual actor proofs and reactivation are required.

## Other unchanged bindings

Keep exact environment/generation/subscription/tenant/cluster ID, actual Kubernetes CA fingerprint, expected principal IDs, fixture UIDs, nonce, timestamps, maximum24hour initial expiry and safe actual allow/HTTP403 outcomes. Proof trust continues to require direct reads from exact actor-owned private Blob containers and create-only writes. Actors cannot overwrite a challenge or read/list consumption records.

Initial consumption validates both private proofs against the current actual cluster/definitions and challenge, then creates a separate consumption/ namespace object under the common native Blob lease. A replay or missing/mismatched object fails. Reviewed activation binds challenge/proof digests, anchor, reviewed source and exact definition manifest. Its ordinary context check never activates from presence alone and does not invent timestamp-driven Argo revocation.

Recurring proofs record their own current actualProbeCodeRevision and anchor, bind the established activation and unchanged exact definition manifest, a fresh nonce/current lease/principal, current cluster CA/roles, safe actual probes and at most15minute phase-start validity. App-only HEAD movement with the proven identical closure does not require a fresh initial apply/other-actor approval. Cleanup remains mandatory after expiry/failure.

## Required intended RED/GREEN evidence

Reject version1/missing fields; dirty tracked/untracked checkout; HEAD/GITHUB_SHA mismatch; correct caller SHA but wrong actual HEAD; changed imported behavior file at otherwise app-only HEAD; changed role/template/current subject; old generation/CA/principal; malformed/expired/replayed challenge. Accept a real clean Git fixture with an app-only later commit and identical closure, while recording distinct reviewed and actually executed SHA. Exercise public producer dispatch and private Blob/actual process boundaries, not a fake qualified flag. Actual hosted Azure identity/API qualification remains an independent live gate.
